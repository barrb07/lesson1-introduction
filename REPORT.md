# Отчёт по Уроку 1: Введение в PyTorch

## 1. Цель работы
Освоить базовые операции с тензорами в PyTorch, понять механизм автоматического дифференцирования (autograd) и провести сравнительный анализ производительности вычислений на CPU и GPU (CUDA).

## 2. Выполненные задачи

### 2.1 Работа с тензорами (`homework_tensors.py`)
- Создание тензоров различными способами: `torch.rand`, `torch.zeros`, `torch.ones`, `torch.arange`.
- Матричные операции (`torch.matmul`) и поэлементные операции (`*`).
- Индексация и срезы многомерных тензоров (включая извлечение центральной подматрицы 2x2 из тензора 5x5x5).
- Изменение формы тензора через `.reshape()` (2x12, 3x8, 4x6, 2x3x4, 2x2x2x3).

### 2.2 Автоматическое дифференцирование (`homework_autograd.py`)
- Вычисление градиентов функции f(x,y,z) = x² + y² + z² + 2xyz через `.backward()`.
- Реализация функции потерь MSE для линейной модели y = wx + b и нахождение градиентов по w и b.
- Проверка цепного правила на функции f(x) = sin(x² + 1) двумя способами: `.backward()` и `torch.autograd.grad`.
- Все градиенты, полученные через PyTorch, совпали с аналитическими значениями.

### 2.3 Сравнение производительности CPU и GPU (`homework_performance.py`)
- Замер времени выполнения 5 операций (matmul, сложение, умножение, транспонирование, сумма) на тензоре размером 128 x 512 x 512.
- Для CPU использовался `time.time()`, для GPU — `torch.cuda.Event` с синхронизацией (учёт асинхронности CUDA).
- Код адаптивен: корректно работает как с GPU, так и без него.

## 3. Результаты сравнения производительности

Таблица замеров для тензора размером **128 x 512 x 512** на GPU **Tesla T4** (Google Colab):

| Операция | CPU (мс) | GPU (мс) | Ускорение (x) |
| :--- | :---: | :---: | :---: |
| Матричное умножение (`matmul`) | 470.79 | 95.72 | **4.9x** |
| Поэлементное сложение | 93.36 | 35.93 | **2.6x** |
| Поэлементное умножение | 89.75 | 19.31 | **4.6x** |
| Транспонирование (`.T`) | 1.89 | 0.04 | **~47x** |
| Сумма всех элементов (`.sum`) | 25.84 | 71.65 | **0.4x** (медленнее) |

### Анализ результатов:
1. **Матричные операции** получают значительное ускорение на GPU (в 4-5 раз для `matmul`), так как видеокарты имеют тысячи ядер, идеально подходящих для параллельных вычислений с высокой арифметической интенсивностью.
2. **Транспонирование** показало наибольшее ускорение (~47x), так как это операция перестановки индексов без реальных вычислений — GPU выполняет её практически мгновенно.
3. **Сумма всех элементов** на GPU оказалась **медленнее** (71.65 мс против 25.84 мс на CPU). Это классический пример: операция слишком простая, и накладные расходы на синхронизацию GPU (`torch.cuda.synchronize()`) и передачу данных перевешивают выгоду от параллелизма. Для таких операций CPU эффективнее.
4. Передача данных между CPU и GPU (метод `.to('cuda')`) занимает время, поэтому в реальных задачах нейросети данные загружаются на видеокарту один раз и хранятся там на протяжении всего цикла обучения.

## 4. Выводы
- Механизм `autograd` является надёжным инструментом: градиенты, вычисленные PyTorch, полностью совпадают с аналитическими производными.
- Для эффективного использования PyTorch критически важно понимать, какие операции выгодно переносить на GPU (матричные вычисления, транспонирование), а какие лучше оставить на CPU (простые редукции типа суммы), чтобы избежать узких мест, связанных с передачей данных и синхронизацией.
- Метод `.reshape()` позволяет менять форму тензора без копирования данных, что делает его эффективным инструментом предобработки.

## 5. Воспроизводимость
Код написан адаптивно: он автоматически проверяет наличие CUDA (`torch.cuda.is_available()`) и корректно работает как на машинах с видеокартой, так и без неё. Все результаты воспроизводимы при фиксированном `random_state`.
